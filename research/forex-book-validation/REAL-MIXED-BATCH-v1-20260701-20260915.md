## Important interpretation

### What worked

1. The replay pipeline handled a real mixed cohort with zero detected future-candle leakage.
2. Success and failure/control observations were evaluated together.
3. Stage transitions were recorded mechanically rather than manually relabeled.
4. `구조훼손` had a materially lower SURGE incidence than the mixed baseline in this cohort.
5. The infrastructure is now large enough to expose weak relationships instead of being dominated by a few memorable successful examples.

### What did not validate

1. The final-state score did not rank future 24H MFE meaningfully.
2. Local quality also had near-zero rank correlation with future 24H MFE.
3. Stage ordinal did not show monotonic upside ordering.
4. `점화대기` / `점화초기` were absent because historical derivative/PRE-SURGE/DNA context was intentionally not substituted with current data.
5. Therefore this batch does **not** validate the Forex Book engine as a standalone PRE-SURGE predictor.

### Why 눌림위험 has a higher surge rate

The `눌림위험` bucket had more SURGE observations than the baseline, but it also had worse median 24H return and larger adverse excursion. This is consistent with a **high-volatility/conflict regime** interpretation and must not be converted into a bullish signal without additional evidence.

## Decision

**Do not connect the current Forex Book score to the main PRE-SURGE scanner.**

Keep the module as:
- structural/context evidence;
- pattern and invalidation support;
- long-risk filtering;
- scenario generation.

The next experiment should test **incremental value**, not merely the standalone score:

1. Freeze this engine version.
2. Add historically timestamped OI / taker / funding / basis only where the data source guarantees as-of correctness.
3. Compare:
   - PRE-SURGE baseline alone
   - Forex Book alone
   - PRE-SURGE + Forex Book
4. Use a time-separated validation period.
5. Report lift, false-positive change, MFE/MAE, and rank correlation.
6. Any parameter change requires a new manifest/version and invalidates the prior validation run.
