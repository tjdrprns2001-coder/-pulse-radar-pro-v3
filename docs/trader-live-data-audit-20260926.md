# 트레이더 스캔 데이터 시각 검증

기준 커밋: `6192c9f`. Oregon 전용 runtime 라우팅, 순차 배치, 사전분류 제외 처리 및 기존 호스트/쿨다운 정책을 유지한다.

## 재현 및 수정

- 시장 전체 스냅샷 15분 캐시와 시세 2분 유효성 조건이 충돌했다. 가상 시각을 3분 진행시키면 정상 후보 2개가 0개로 바뀌는 테스트로 재현했다.
- 목록 메타데이터는 15분 보관하고, 전체 시세·BTC/ETH 상태를 공유 60초 캐시로 갱신한다. 종목별 시세 호출을 추가하지 않으며 동시 갱신 요청은 합친다. 갱신 실패 시 오래된 시세를 현재 시각으로 바꿔 통과시키지 않는다.
- 결과 유효성을 전체 스캔 완료 시각으로 계산해 오래된 초기 결과가 최신처럼 표시되는 문제를 종목별 `asOf` 기준으로 수정했다. 2분 지난 진입 확인은 재확인 대상으로 표시한다.
- `GUSDT`와 같은 1글자 기초자산 심볼을 목록에 포함하고도 검증 정규식에서 거절하던 오류를 수정했다.
- 각 결과의 `dataAudit`에 PREFILTER/DEEP 검사 단계, 시세 원시 시각/판정 당시 경과 시간, 시장 상태 조회 시각, OI/taker 시각, TF별 마지막 확정봉·봉 수·가용성을 기록한다. 화면의 출처·기준 시각 패널에서 확인 가능하다.

## 검증 범위

- `scripts/verify-trader-freshness.js`: 장시간 스캔, 갱신 요청 공유, 목록 캐시 유지, 시세 갱신 실패, 저유동성 사전 제외 시 6TF 호출 생략, 1글자 심볼, 출처 시각.
- `scripts/verify-trader-result-age.js`: 종목별 2분 만료, 시각 누락·미래 시각.
- jsdom 통합검사: 새/오래된 결과가 서로 다른 상태로 표시되고, 데이터 출처 패널과 펼침 상태가 유지됨.
- `npm run verify`는 `test:v4-1-mobile`의 `child view cache-bust missing`에서 중단됨. 테스트는 `20260921-v5`를 기대하지만 기준 커밋의 셸은 이미 `20260926-trader-astra1`을 사용한다. 이번 변경에서 두 파일을 수정하지 않았음을 확인했다. 전체 검증 통과로 보고하지 않는다.

## 운영 확인 대기

알고 있던 `https://pulseradar-pro-v5.netlify.app/api/coin-scan?mode=trader-summary`는 이번 조회에서 `usage_exceeded`를 반환했다. 따라서 사용자가 정상 사용 중이라고 알린 새로운 N사이트/Oregon runtime의 실데이터에는 아직 연결하지 못했다. 527개/105개 및 418·429 미발생은 사용자가 전달한 직전 결과이며 이번 검증의 실측 수치가 아니다.

다음 운영 확인은 현재 사이트 URL 또는 runtime URL이 확인되면 순차적으로 실시한다: 전체 요약 1회 → 사전 제외 종목 1개 → 정밀 대상 소수 → 시각·누락·원시 수치 교차검증. 실데이터 수익성 검증과 운영 배포는 이번 코드 검증에 포함되지 않는다.
