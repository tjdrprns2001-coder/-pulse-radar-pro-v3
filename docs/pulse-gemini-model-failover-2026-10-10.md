# Pulse AI Gemini 모델 자동 전환 — 2026-10-10

## 실제 구현

기존 Pulse AI의 Gemini 단일 모델 호출을 **최대 3개 모델의 자동 순차 전환**으로 변경했다. 프로젝트의 API 키는 기존 Render 환경 변수 `GEMINI_API_KEY`를 그대로 사용한다. 별도의 인증키 발급이나 사용자 UI 수동 모델 전환은 불필요하다.

기본 순서:
1. `GEMINI_MODEL` 설정값 (미설정 시 `gemini-3.8-flash`)
2. `gemini-3.5-flash-lite`
3. `gemini-3.5-flash`

**적용 경로:** 일반 브리핑, Gemini 챗봇 답변, 사용자가 버튼으로 시작하는 상승·하락·위험 3역할 LLM 심의. Google AI 모델 문서에서 지원되는 Flash/Flash-Lite 제품군만 기본 후보로 정했다. 모델을 직접 하드코딩된 단일 모델에 고정하지 않으며 환경 변수 `GEMINI_FALLBACK_MODELS`를 이용해 허용 목록을 변경할 수 있다. 전환 모델 수는 요청당 **설정 기본 모델을 포함해 최대 3개**다.

**트리거:** 429(사용량 제한), 404(접근 불가/잘못된 모델), 500·502·503·504(서버 장애) 응답. 각 모델은 요청당 기본 한 번만 호출하고, 문제가 있는 모델은 인스턴스 내에서 429/5xx는 2분, 404는 1시간 대기 후 재시도한다.

**예외:** 400(잘못된 요청), 401(키/인증 문제), 403(권한 문제)는 기본적으로 모델을 변경하지 않는다. 다만 검색 근거 연결을 사용할 때 400/403이면 기존과 동일하게 검색 없이 동일 모델에서 한 번 재시도한다. 프로젝트/결제 전체 할당량 초과임이 오류 본문에서 명백하면 모델을 무작정 연속 호출하지 않는다. 3개 모델 모두 사용 불가 시 안전하게 기존 규칙 기반 분석으로 되돌아간다.

**관측 가능성:** `gateway.health()`는 현재 사용 모델, 후보 모델, 대기 중인 모델, 전환 횟수, 실제 Gemini HTTP 시도 수를 반환한다. `roleDebate.modelRouting`으로 읽기 전용 상태가 API에 표시된다. Gemini 3역할 심의 시 각 역할의 `modelUsed` 및 전체 `modelsUsed`를 명시하며, 모델 폴백 시 증가하는 HTTP 시도 횟수도 `modelCalls`로 기록한다. API 키와 원격 예외 본문은 모델 응답에 노출하지 않는다.

## 검증

- `scripts/verify-pulse-ai-gateway.js`: 기존 API 연결 테스트를 429 자동 모델 전환 후 성공 시나리오로 보강
- `scripts/verify-pulse-ai-model-failover.js`: 주모델 429, 대체 모델 성공, 냉각기간 동안 원모델 생략, 다음 번 냉각 해제, 2개 실패 후 3번째 성공, 역할별 모델 기록, 프로젝트 전체 소진 시 조기 중단, 인증 문제 중단, 전체 모델 실패 냉각, Google 검색 비활성 폴백까지 확인
- `.github/workflows/check-pulse-ai-v2.yml`: 기본 브랜치 CI에서 기존 Pulse AI 테스트와 신규 자동 전환 테스트 실행
- 정적 파일 `pulse-ai.html`의 JS 캐시 키 갱신 및 `ui/pulse-ai.js` 모델 선택 상태 표시

**중요한 주의점**

- Google은 모델별·프로젝트별 분당 요청, 분당 토큰, 일일 요청량 및 결제 한도를 적용한다. 모델을 바꿔도 **프로젝트 전체 청구·할당량 문제는 해결되지 않는다.**
- 별도 제공자에 모델을 옮기는 기능이 아니다. 세 모델 모두 **동일 Google AI Studio 프로젝트/키**를 사용한다.
- 자동 전환은 **생성형 모델 서비스 가용성만 개선**한다. 3역할 AI 기능을 막는 원격 스캔 `partial`, OI/체결 데이터 누락 등 품질 게이트는 제거하지 않는다.
- Gemini 모델은 가격과 사용한도가 다를 수 있다. 기본 대체 모델은 Flash-Lite/Flash로 제한하고 모델 개수를 세 개로 제한했지만, 실제 계정별 이용 요금·무제한 무료 호출을 보장하지 않는다.
- 냉각/총 사용량 계수는 **프로세스 내 메모리**라 인스턴스 재시작/다중 Render 인스턴스에 공유되지 않는다.
- 코드·모의 응답 자동 테스트 통과와, Render 운영 배포 및 **실제 Gemini API 모델 생성 성공**은 별도 확인 항목으로 분리해야 한다.
